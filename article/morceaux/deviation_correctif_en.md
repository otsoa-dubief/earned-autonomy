**Final replay: a code defect and its in-memory fix.** The final replay launched with the deposited command failed after 4,614 s while writing the stress-test table (`resistance.csv`): the frozen function `lignes_resistance` passed two `mode` keys to the same record, a case that never arose in the pilot because no stress-test cell was judged there. The frozen code was not edited, since the engine refuses to run if the repository differs from the frozen manifest. Instead, a wrapper script (`outils/rejeu_final_correctif.py`) replaced that single function in memory, renaming the second field `mode_scenario`, and called the engine's entry point with exactly the deposited arguments. Strictly speaking, this is therefore not the same command. The run metadata (`meta.json`) records the fingerprint of the frozen `sorties.py` and says nothing about the in-memory replacement; a separate note documents it. The replaced function only formats `resistance.csv`, which therefore has one extra column, and it is called after the label has been computed, so the label does not depend on it. The six tables written by both runs are byte-identical, as checked independently on fingerprints alone.
